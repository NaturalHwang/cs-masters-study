1. 오늘의 주제

CPU·Memory·Storage의 역할을 구분하고, 프로그램(Program)이 프로세스(Process)로 실행되는 흐름과 운영체제(Operating System, OS)의 역할을 이해한다.

2. 학습 목표

  • CPU·Memory·Storage 역할 설명
  • Program과 Process 구분
  • OS가 실행을 관리하는 이유 설명
  • 같은 프로그램의 여러 Process가 가능한 이유 설명

3. 이전 학습과의 연결

첫 회차다. 앞으로 Program → Process → Memory → Thread → Concurrency → Network → DB → Distributed System으로 연결한다.

4. 필요한 선수지식과 3~5분 복습

Instruction

CPU가 실행하는 작은 명령 단위.

Address

메모리 위치를 찾기 위한 번호.

Function Call

호출 위치와 돌아갈 위치 등 실행 상태가 필요하다.

5. 문제 상황

inventory-server 파일이 SSD에 있어도 요청을 처리하지 못한다. 실행 위치, 변수 공간, CPU 사용 순서, I/O 접근을 누군가 준비·관리해야 한다.

6. 핵심 개념

요소역할
Storage프로그램·데이터의 지속 보관
Memory실행 중 코드·데이터 작업 공간
CPU명령 실행

Program은 정적인 명령·데이터 표현이고, Process는 실행 상태를 가진 동적 인스턴스다.

Storage → OS가 실행 환경 준비 → Memory 사용 → CPU 실행
                         ↕
                      System Call / I/O

OS는 추상화, 자원 관리, 보호·격리, 실행 관리를 제공한다.

7. 실제 시스템 사례

Unix 계열에서는 프로세스 생성과 프로그램 이미지 교체를 구분한다. Linux의 execve()는 현재 프로세스의 프로그램 이미지를 새 프로그램으로 교체한다.

8. Trade-off와 대안

OS 추상화와 Process Isolation은 안전성과 관리 편의성을 주지만 스케줄링·주소 변환·시스템 호출 같은 관리 비용을 만든다.

9. 간단한 심화

Process ≈ Program Image
        + Address Space
        + CPU Register State
        + Open Resources
        + OS bookkeeping

“RAM에 올라온 파일”만으로는 프로세스를 충분히 설명할 수 없다.

10. 핵심 요약

  1. Storage=지속 보관, Memory=실행 작업 공간, CPU=명령 실행.
  2. Program과 Process는 다르다.
  3. 같은 Program에서도 여러 Process가 가능하다.
  4. OS는 자원을 관리하고 격리를 제공한다.
  5. 실행은 상태 준비와 지속적인 CPU·OS 상호작용이다.

11. 확인 질문 3~5개와 접이식 해설

Q1 Program과 Process 차이는?

해설

Process에는 현재 실행 상태가 포함된다.

Q2 SSD가 있는데 RAM이 왜 필요한가?

해설

지속 저장과 빠른 실행 작업 공간의 역할이 다르다.

Q3 같은 프로그램 두 실행의 변수 값은 항상 같은가?

해설

아니다. 각 Process는 독립 실행 상태를 가질 수 있다.

Q4 실행 추적

파일 보존→Storage, 실행 환경 준비→OS/Memory, 덧셈 실행→CPU, 변수 읽기→CPU/Memory로 연결해 보라.

해설

실제 시스템에서는 구성 요소가 협력하며 역할 경계를 구분하는 것이 핵심이다.

12. 연구자의 관점

Process startup cost, isolation vs overhead, CPU scheduling의 latency·throughput·fairness를 관찰 변수로 생각해볼 수 있다.
