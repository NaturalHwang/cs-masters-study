1. 오늘의 주제

Process와 Thread의 차이, Shared Memory, 개별 Stack·Register, Context Switching을 이해한다.

2. 학습 목표

  • Process vs Thread 구분
  • Thread가 공유하는 것과 개별 보유 상태 설명
  • Context의 의미 설명
  • Context Switching이 왜 필요한지 이해

3. 이전 학습과의 연결

Day02에서 Process마다 Address Space가 있음을 배웠다. 오늘은 한 Address Space 안에 여러 실행 흐름이 있을 수 있음을 본다.

4. 필요한 선수지식과 3~5분 복습

Code/Data/Heap/Stack을 복습한다. 함수 호출과 CPU Register는 현재 실행 위치를 표현하는 데 필요하다.

5. 문제 상황

서버가 한 요청의 disk/network I/O를 기다리는 동안 다른 요청까지 멈춰야 할까? 여러 실행 흐름이 있으면 대기 중에도 다른 일을 진행할 수 있다.

6. 핵심 개념

Thread는 Process 안의 실행 흐름이다.

공유Thread별 개별 상태
Code, Data, Heap, 열린 Process 자원 다수Stack, Register state, Instruction Pointer 등
Process
┌────────────────────┐
│ Code / Data / Heap │ ← shared
│ Thread A Stack     │
│ Thread B Stack     │
└────────────────────┘

Context는 실행을 멈췄다가 다시 이어가기 위해 필요한 상태다. Context Switching은 실행 주체를 바꾸며 이전 상태를 저장하고 다음 상태를 복원하는 과정이다.

7. 실제 시스템 사례

일반적인 서버 런타임은 여러 요청을 여러 Thread 또는 유사 실행 단위로 처리할 수 있다. 실제 스레딩 모델은 언어·런타임·서버에 따라 다르므로 특정 프레임워크 동작으로 일반화하지 않는다.

8. Trade-off와 대안

많은 Thread적은 Thread
I/O 대기 동안 다른 작업 진행 가능상태·스케줄링 비용 감소
메모리·스케줄링·동기화 복잡성 증가Blocking 작업이 많으면 활용도 저하 가능

9. 간단한 심화

Process context switch와 Thread context switch의 비용은 상황과 구현에 따라 다르다. “Thread switch는 항상 매우 싸다”처럼 절대화하지 않는다.

10. 핵심 요약

  1. Process는 자원과 주소 공간의 큰 경계, Thread는 그 안의 실행 흐름이다.
  2. Thread들은 많은 메모리를 공유한다.
  3. 각 Thread는 자기 Stack·Register 실행 상태가 필요하다.
  4. Context Switching은 실행을 이어가기 위한 상태 교체다.
  5. 공유는 효율을 주지만 동기화 문제의 출발점이 된다.

11. 확인 질문 3~5개와 접이식 해설

Q1 Thread 둘이 같은 Heap 객체를 볼 수 있는가?

해설

같은 Process라면 공유 주소 공간의 Heap을 함께 사용할 수 있다.

Q2 왜 Stack은 보통 Thread별로 필요한가?

해설

각 Thread가 독립 함수 호출 흐름과 지역 상태를 가져야 하기 때문이다.

Q3 Register state는 왜 Context에 포함되는가?

해설

현재 계산과 실행 위치를 나중에 이어가기 위해 필요하다.

Q4 실행 추적

A가 함수 내부에서 멈추고 B가 실행된 뒤 다시 A로 돌아올 때 저장·복원해야 할 상태를 적어보라.

해설

최소한 실행 위치와 관련 register state, stack pointer 등 실행 문맥이 필요하다.
