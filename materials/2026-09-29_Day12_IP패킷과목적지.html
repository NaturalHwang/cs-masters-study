1. 오늘의 주제

Day11의 Application·Transport·IP·Link 계층 중 IP를 확대한다. 핵심은 IP Address, IP packet, Router다.

2. 학습 목표

  • IP Address의 역할을 설명한다.
  • Source/Destination Address와 TTL/Hop Limit의 의미를 설명한다.
  • Router가 다음 hop을 고르는 흐름을 설명한다.
  • IP가 손실·지연·재정렬 가능성을 제거하지 않는다는 점을 이해한다.

3. 이전 학습과의 연결

Application Message

Transport
      ↓

Link

Application은 업무 의미를 알고, IP는 목적지 쪽으로 데이터를 전달하는 책임을 가진다.

4. 필요한 선수지식과 3~5분 복습

Header는 계층이 전달에 필요한 제어 정보를 담는 부분이다. Host는 네트워크에 참여하는 시스템이고, Hop은 한 네트워크 장치에서 다음 장치로 이동하는 한 단계다.

IP Address는 Process ID가 아니라 IP 계층의 네트워크 주소다.

5. 문제 상황

Client와 Server가 서로 다른 네트워크에 있으면 둘 사이에 여러 Router가 있을 수 있다. Client가 전체 경로를 직접 계산하는 대신 각 Router가 목적지 주소를 보고 다음 방향을 선택하는 방식으로 packet이 이동한다.

6. 핵심 개념

6.1 IP Address

IPv4는 32bit, IPv6는 128bit 주소를 사용한다. IP Address는 source와 destination을 표현하는 네트워크 계층 주소다.

6.2 IP packet

6.3 Router

Router는 Destination Address와 자신의 forwarding 정보를 이용해 다음 hop 또는 출력 interface를 선택한다.

Destination Address 확인

6.4 Prefix

Router는 주소 하나하나가 아니라 주소의 앞부분인 prefix를 이용해 네트워크 범위를 묶어 전달 규칙을 관리할 수 있다.

6.5 IP의 보장 범위

IP는 end-to-end delivery, ordering, retransmission, exactly-once 처리를 보장하지 않는다. RFC 1122는 IP datagram이 손상, 중복, 순서 변경, 미도착할 수 있다고 설명한다.

정확한 표현: IP가 항상 실패한다는 뜻이 아니라, IP 계약 자체가 이러한 신뢰성을 보장하지 않는다는 뜻이다.

6.6 TTL / Hop Limit

IPv4의 TTL과 IPv6의 Hop Limit은 packet이 routing loop 안에서 무한히 전달되는 것을 막기 위해 forwarding될 때 감소한다.

9. 간단한 심화

Address는 어디로 가는지 표현하고, Route/forwarding decision은 다음에 어디로 넘길지 결정한다. 둘은 같은 개념이 아니다.

IPv4의 TTL은 이름과 달리 현대 forwarding에서는 hop-count 성격이 중요하며, IPv6는 이를 Hop Limit이라 부른다.

10. 핵심 요약

  1. IP Address는 IP 계층의 source/destination 주소다.
  2. IP packet은 목적지 주소와 상위 계층 데이터를 운반한다.
  3. Router는 목적지 주소와 forwarding 정보를 사용해 다음 hop을 고른다.
  4. IP는 delivery와 ordering을 보장하지 않는다.
  5. TTL/Hop Limit은 무한 forwarding을 제한한다.

11. 확인 질문 3~5개와 접이식 해설

Q1. IP Address가 Process를 직접 식별하는가?

해설 보기

아니다. IP Address는 네트워크 계층 주소다. 한 host 안 여러 서비스의 구분은 Transport의 Port/Socket과 연결된다.

Q2. Router가 JSON body를 이해해야 하는가?

해설 보기

기본 IP forwarding에서는 Destination Address와 forwarding 정보가 핵심이다.

Q3. packet 전송만으로 업무 성공을 보장할 수 있는가?

해설 보기

아니다. 네트워크 전달과 Application 처리 성공은 서로 다른 사건이다.

Q4. 3~5분 실행 추적

Client → Router A → Router B → Server
Hop Limit = 3

각 Router에서 Hop Limit을 1씩 줄여 Server에 도달 가능한지 판단해보라.

해설 보기

Router A 이후 2, Router B 이후 1이 되어 Server까지 도달 가능하다. 중간 Router 수가 더 많아 0에 도달하면 더 forwarding되지 않는다.

Q5. 먼저 보낸 packet이 반드시 먼저 도착하는가?

해설 보기

IP는 end-to-end ordering을 보장하지 않는다.
