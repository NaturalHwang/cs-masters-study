1. 오늘의 주제

주소 공간(Address Space), Code/Data, Stack/Heap, Process Isolation의 큰 그림을 이해한다.

2. 학습 목표

  • Address Space 정의
  • Code/Data/Heap/Stack 역할 구분
  • Virtual Address와 Physical Memory의 차이 이해
  • Process Isolation의 필요성 설명

3. 이전 학습과의 연결

Day01의 “Process = Program + 실행 상태”에서 메모리 부분을 구체화한다.

4. 필요한 선수지식과 3~5분 복습

변수는 실행 중 메모리 위치와 연결되고, 함수 호출은 지역 상태와 복귀 정보를 필요로 한다. 오늘은 Page Table/TLB 세부는 다루지 않는다.

5. 문제 상황

Process A: virtual 0x1000 → stock
Process B: virtual 0x1000 → userCount

주소 숫자가 같은데도 왜 충돌하지 않는가?

6. 핵심 개념

Address Space는 한 Process가 사용할 수 있다고 보는 주소의 논리적 세계다.

높은 주소
┌──────────┐
│ Stack    │
│    ↓     │
│          │
│    ↑     │
│ Heap     │
├──────────┤
│ Data     │
├──────────┤
│ Code     │
└──────────┘
낮은 주소

각 Process의 Virtual Address는 OS와 hardware의 mapping을 통해 서로 다른 Physical Page로 이어질 수 있다.

7. 실제 시스템 사례

Linux의 /proc/<pid>/maps는 한 Process의 가상 주소 범위, 접근 권한, 파일 mapping 등을 보여준다.

8. Trade-off와 대안

접근장점대가
독립 주소 공간격리·보안IPC 필요, 주소 관리 비용
Shared Memory빠른 공유동기화 복잡성
Message Passing경계 명확직렬화·복사 비용 가능

9. 간단한 심화

Virtual Address → 주소 변환 → Physical Page → RAM

Virtual Memory는 단순히 RAM 부족 시 disk 사용 기능만을 뜻하지 않는다. 주소 공간 추상화와 격리가 핵심 역할이다.

10. 핵심 요약

  1. Address Space는 Process가 보는 논리적 주소 세계다.
  2. Code/Data/Heap/Stack으로 큰 역할을 나눠 볼 수 있다.
  3. 같은 Virtual Address가 같은 Physical Address를 뜻하지 않는다.
  4. Process Isolation은 안정성과 보안의 기반이다.
  5. 의도적으로 Shared Memory를 만들 수도 있다.

11. 확인 질문 3~5개와 접이식 해설

Q1 Address Space가 RAM의 연속 구간이라는 설명이 왜 부정확한가?

해설

가상 주소의 논리적 공간이며 물리 RAM과의 mapping이 별도다.

Q2 Stack과 Heap 차이는?

해설

Stack은 함수 호출 상태와 밀접하고, Heap은 동적 메모리와 밀접하다.

Q3 Isolation이 없다면?

해설

다른 Process의 메모리 침범과 오류 전파 위험이 커진다.

Q4 실행 추적

A: virtual 0x1000 → physical page 5 → 10
B: virtual 0x1000 → physical page 9 → 50

A가 11을 쓰면 각 Process는 무엇을 읽는가?

해설

A=11, B=50. mapping이 다르기 때문이다.
